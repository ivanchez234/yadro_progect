# YadroVad — воспроизведение речи без пауз

[![CI](https://github.com/ivanchez234/yadro_progect/actions/workflows/ci.yml/badge.svg)](https://github.com/ivanchez234/yadro_progect/actions/workflows/ci.yml)

Свой элемент GStreamer на C++, который на лету вырезает паузы из речи, и плеер на Qt 6 поверх него. Подходит для лекций, подкастов и голосовых сообщений: тишина выбрасывается, остаток склеивается без щелчков и при желании ускоряется без изменения высоты голоса.

- **`yadrovad`** — элемент GStreamer (`GstBaseTransform`). Решение «речь/тишина» принимает [libfvad](https://github.com/dpirch/libfvad) (WebRTC VAD). Сам элемент написан с нуля: нарезка на кадры, удержание после речи, пересчёт меток времени, телеметрия.
- **YadroPlayer** — плеер на Qt 6 Widgets. Агрессивность VAD, удержание и скорость меняются во время воспроизведения.
- **`yadrovad_cli`** — то же самое из консоли: воспроизведение, запись в WAV, статистика в JSON.
- **Тесты**: 9 модульных на `GstHarness` и сквозной через настоящий конвейер. CI на GitHub Actions, отдельный прогон под AddressSanitizer/UBSan.
- **Стенд точности**: покадровое сравнение с нейросетевым Silero VAD на LibriSpeech.

## Как это работает

```
playbin (filesrc → decodebin)
   └─ audio-filter: audioconvert → audioresample → yadrovad → audioconvert → pitch
                                 16 кГц, моно, S16LE   ↑ свой элемент
```

**Кадры.** Вход копится в `GstAdapter` и режется на кадры по 30 мс (480 сэмплов = 960 байт). Это один из размеров кадра, которые принимает WebRTC VAD. Каждый кадр классифицирует `fvad_process()`.

**Удержание (hangover).** Если выбрасывать всё, что VAD назвал тишиной, обрезаются окончания слов: затухающие согласные VAD часто считает тишиной. Поэтому после последнего кадра речи ещё N кадров проходят дальше:

```
SILENCE ──речь──▶ SPEECH ──не речь──▶ HANGOVER (N кадров) ──▶ SILENCE
                    ▲                        │
                    └──────────речь──────────┘
```

N = ⌈`hangover-time` / 30 мс⌉: значение 210 мс даёт ровно 7 кадров, удержание никогда не короче заявленного.

**Метки времени.** У сохранённых кадров PTS пересчитываются встык: `out_time += 30 мс`. Поток на выходе непрерывный, и аудиоприёмник не ждёт вырезанные паузы. На склейках ставится `GST_BUFFER_FLAG_DISCONT`. Время на выходе принадлежит элементу, поэтому входной `SEGMENT` заменяется своим (после перемотки входной сегмент начинается не с нуля, и приёмник выбросил бы буферы). На `FLUSH_STOP` адаптер и автомат сбрасываются.

**Работа с `GstBaseTransform`.** Элемент переопределяет `submit_input_buffer` и `generate_output`, потому что выходных буферов не столько же, сколько входных. Базовый класс вызывает `generate_output` в цикле до первого `NULL`, поэтому `NULL` возвращается только тогда, когда в адаптере не осталось целого кадра. Кадры тишины пропускаются внутри собственного цикла. Именно здесь была главная ошибка первой версии (см. ниже).

**Потоки.** Ползунки плеера меняют свойства из потока GUI, а `fvad` работает в потоке обработки. Свойства хранятся под `GST_OBJECT_LOCK`. Сам `fvad_set_mode()` вызывается только из потока обработки перед следующим кадром, поэтому `fvad` никогда не используется из двух потоков сразу.

**Телеметрия.** На EOS элемент отправляет на шину сообщение `YadroVadStats`: `total_frames`, `frames_kept`, `frames_dropped` и маску решений (`'1'` — кадр оставлен, `'0'` — вырезан). Плеер показывает по ней итог, стенд точности сравнивает маску с эталоном.

**Плеер.** Конвейер строится на `playbin` со свойством `audio-filter`. Путь к файлу передаётся как URI, а не подставляется в текст конвейера, поэтому пробелы и кавычки в имени файла ничего не ломают. Сообщения шины забирает `gst_bus_set_sync_handler` и перекладывает в поток GUI через `QMetaObject::invokeMethod`. Так плеер не зависит от цикла событий GLib.

## Найденная ошибка и как её поймали

В первой версии `generate_output` возвращал `NULL` на каждом кадре тишины. Базовый класс воспринимал это как «данных больше нет» и переходил к следующему входному буферу, а остаток текущего копился в адаптере до конца файла и там терялся. На MP3 44,1 кГц это было почти незаметно: после ресемплинга буферы короче одного кадра. А `wavparse` отдаёт WAV 16 кГц буферами по 4096 байт, примерно 4 кадра. На тестовом сигнале из трёх фраз из 243 кадров обрабатывалось 98, а вторая и третья фразы пропадали целиком.

Тесты в `tests/` написаны так, что на старом коде (тег `v0.1-original`) 7 из 9 модульных тестов и сквозной тест падают, а на новом всё проходит:

| Проверка | Старый код | Новый |
|---|---|---|
| Учтены все кадры входа (буферы 4096 / 960 / 100 / 16000 байт) | 98 из 243 | 243 из 243 |
| Все три фразы дошли до выхода | 1 из 3 | 3 из 3 |
| Удержание 210 мс = 7 кадров | 6 | 7 |
| Только тишина 6,4 с: учтены все кадры | 50 из 213 | 213 из 213 |
| Перемотка: сегмент с нуля, хвост до flush выброшен | ✗ | ✓ |
| Сквозной тест WAV → `playbin` → `yadrovad` | 98 из 243 | 243 из 243 |

## Сборка и запуск (Ubuntu 24.04)

```bash
sudo apt install build-essential cmake pkg-config \
    libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
    gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
    gstreamer1.0-plugins-bad \
    qt6-base-dev

cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

- `gstreamer1.0-plugins-bad` нужен только для элемента `pitch` (изменение скорости). Без него плеер работает, но ползунок скорости отключён.
- Без Qt можно собрать только плагин, CLI и тесты: `-DYADROVAD_BUILD_PLAYER=OFF`.

**Плеер:**

```bash
./build/player/YadroPlayer               # выбрать файл кнопкой
./build/player/YadroPlayer lecture.mp3   # открыть и сразу играть
```

Плагин плеер ищет сам: сначала в `GST_PLUGIN_PATH`, потом в `build/gst-plugins`.

**Консоль:**

```bash
./build/tools/yadrovad_cli lecture.mp3                    # слушать
./build/tools/yadrovad_cli --tempo 1.5 lecture.mp3        # быстрее, без «мультяшного» голоса
./build/tools/yadrovad_cli --out short.wav lecture.mp3    # записать результат
./build/tools/yadrovad_cli --null --json lecture.mp3      # статистика и маска кадров
```

**Из любой программы на GStreamer:**

```bash
export GST_PLUGIN_PATH=$PWD/build/gst-plugins
gst-inspect-1.0 yadrovad
gst-launch-1.0 filesrc location=lecture.mp3 ! decodebin ! audioconvert ! audioresample ! \
    yadrovad vad-mode=2 hangover-time=210 ! audioconvert ! autoaudiosink
```

| Свойство | Диапазон | По умолчанию | Смысл |
|---|---|---|---|
| `vad-mode` | 0–3 | 3 | агрессивность WebRTC VAD: чем выше, тем больше кадров считается тишиной |
| `hangover-time` | 0–2000 мс | 210 | сколько звука оставлять после конца речи |

Оба свойства можно менять во время воспроизведения.

## Стенд точности

Эталон — [Silero VAD](https://github.com/snakers4/silero-vad), нейросетевой VAD, заметно точнее WebRTC VAD. Это не ручная разметка, поэтому метрика называется **согласием с Silero**, а не абсолютной точностью. Набор: по 10 клипов из LibriSpeech dev-clean трёх видов: чистая речь, речь с розовым шумом и только шум. Сравнение покадровое, по 30 мс.

```bash
cd benchmark
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu

python3 build_dataset.py      # скачать LibriSpeech и собрать клипы (нужен ffmpeg)
python3 silero_masks.py       # эталонные маски
python3 plugin_masks.py       # маски плагина для vad-mode 0..3 (hangover 0)
python3 evaluate.py           # таблица в Markdown
```

## Ограничения

- Внутри элемента звук всегда 16 кГц моно, перед ним стоит `audioresample`. Для речи этого достаточно, но на выходе нет исходного качества музыки.
- WebRTC VAD — модель на энергиях полос частот. На шуме он ошибается заметно чаще нейросетевых VAD, это видно на стенде.
- Статистика приходит только в конце файла (на EOS).
- Время на выходе сжатое, поэтому позиция воспроизведения не совпадает с позицией в исходном файле. Перемотку элемент корректно переживает, но в плеере её нет.
- Проверено на Linux (Ubuntu 24.04). Код от Linux не зависит, но под Windows и macOS не собирался.

## Структура

```
plugin/        элемент yadrovad (gst_yadro_vad.cpp/.h)
player/        плеер на Qt 6
tools/         yadrovad_cli
tests/         модульные тесты (GstHarness) и сквозной тест
benchmark/     стенд точности против Silero VAD (Python)
third_party/   libfvad — WebRTC VAD, BSD-3-Clause, без изменений
```
